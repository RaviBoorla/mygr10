# Enhancement ideas

Not scheduled unless marked done — just captured for later.

- **Difficulty filter** in Mock/Drill. *(done)* Each subject card has an All/Easy/Medium/Hard selector filtering both modes.
- **Progress tracking** — weak-chapter analytics from test history. *(done)* New "Progress" screen (header nav) shows per-chapter accuracy, weakest first, built from a persistent Leitner-box record per question.
- **Bookmark/flag questions** for later review, independent of a test session. *(done)* Star button on every question (test-taking and results review); a "Bookmarked" link appears on the subject card once you have any, starting a review session over just those questions.
- **Timestamp on attempts** — dates already existed; now every attempt (mock/drill/bookmark/review) records a full date+time and Recent Attempts shows it. *(done)*
- **Spaced-repetition drill queue.** *(done)* Every graded attempt updates a Leitner box per question (box↑ on correct, resets to 0 on wrong; due date = now + interval for that box: 0/1/3/7/14/30 days). A "Due for review" link appears on the subject card and in Progress once anything is due, starting a review session over just the due questions.
- **ICSE/IB question banks** — only CBSE has real content; other boards' subjects say "coming soon."
- **PWA/offline support** — installable, works without network. *(in progress)* `public/manifest.json` (icons in `public/icons/`, generated from the existing bar-chart favicon mark) + a minimal network-first `public/sw.js` are wired into `index.html`, making the site installable and giving it an offline fallback for previously-visited pages. This is also the foundation for the Play Store listing below.
- **Play Store listing (Android, via Trusted Web Activity)** — *(in progress)* Wraps the live site at `https://rise.strat101.com` in a TWA shell instead of bundling a content snapshot, so question-bank updates go live instantly with no new Play Store release needed. `public/.well-known/assetlinks.json` is scaffolded (package name `com.strat101.rise`) but the `sha256_cert_fingerprints` placeholder must be replaced with the real value once the Android signing key is generated (via Bubblewrap or PWABuilder — see below), and `public/privacy.html` is a fresh, accurate policy: no accounts, no personal-data collection, everything client-side. Remaining steps require tools not available in this sandbox (no local Android SDK access, and this sandbox's outbound network policy blocks `dl.google.com`/Gradle downloads) plus a real Google Play Console account, so they're for whoever runs the build locally:
  1. Deploy this branch's `public/` changes so `manifest.json`, `sw.js`, `icons/`, and `privacy.html` are live on `rise.strat101.com`.
  2. Generate the Android project + signing key. Easiest: go to [pwabuilder.com](https://www.pwabuilder.com), enter `https://rise.strat101.com`, and use its Android package option (uses package name `com.strat101.rise`) — it builds the signed AAB/APK entirely in the browser, no local Android SDK needed. (Alternative: `npx @bubblewrap/cli init --manifest=https://rise.strat101.com/manifest.json` locally, which needs a JDK 17 + Android SDK it can install for you.)
  3. From that build, copy the SHA-256 signing certificate fingerprint into `public/.well-known/assetlinks.json`'s placeholder, deploy again, and confirm `https://rise.strat101.com/.well-known/assetlinks.json` serves the real fingerprint (Play Store verifies this before trusting the TWA to open without a browser address bar).
  4. Create a Google Play Console account ($25 one-time), create the app listing, set the privacy policy URL to `https://rise.strat101.com/privacy.html`, fill in the store listing (screenshots, description, content rating questionnaire — likely "Everyone"/no age restriction given it's exam-prep content), and upload the AAB from step 2.
- **Explanations toggle in results** — *(done)* Results review now shows an optional "Why the others are wrong" block per question, listing per-distractor reasoning for each wrong option (correct-answer's own explanation is unchanged). Schema: an optional `whyWrong` array (4 entries, index-aligned with `options`, empty string at the correct index) on any question object; entirely additive and backward-compatible — questions without it render exactly as before. Authored so far for the "Map Work" chapter of X-ICSE-Geography.json (11 questions) plus every real board-paper-sourced question in X-CBSE-Hindi.json (88 of 125; the 37 unseen-passage questions are skipped since the source passage isn't stored in the bank), X-CBSE-Mathematics.json (all 158 real questions, covering 2023–2026), X-CBSE-Science.json (all 120 real questions) and X-CBSE-Social-Science.json (all 80 real questions, covering 2023–2026); extending to the remaining ~1,300 non-real-board-sourced questions across the ICSE banks is pure content-authoring effort, one chapter/bank at a time.
- **Streaks/daily goal** nudges to build a study habit. *(done)* Home screen shows a "🔥 N-day streak" banner once the student has completed at least one graded attempt on that grade+board; a day counts once any mock/drill is submitted with ≥1 answered question, consecutive days increment the streak, a gap resets it to 1 (longest streak kept separately). A daily goal (30 questions) shows a progress bar that stays visible (green, capped at 100%) once met. Scoped per "grade::board" (same isolation as progress/bookmarks) — practicing X-CBSE builds its own streak, separate from XII-CBSE or X-ICSE.
- **Optional login + Firebase sync** — so streaks/progress/bookmarks/results survive a cleared browser and follow the student across devices, instead of living only in that browser's localStorage. Plan (not yet built):
  - Firebase free (Spark) tier is sufficient: Authentication is free regardless of provider/user count; Firestore's free quota (1 GiB storage, 50K reads/20K writes/20K deletes per day) comfortably covers this app's write pattern (a handful of small doc writes per submitted attempt, not per question).
  - Sign-in via email/password and Google.
  - Login stays optional — the app keeps working exactly as today (localStorage-only) for anyone who doesn't log in. Logging in additionally syncs local data to Firestore, keyed by the user's UID, and merges it across devices.
  - Must be real login, not Firebase "anonymous auth" — anonymous sessions are tied to the device and would be lost along with everything else on a cleared browser.
  - Needs: a Firebase project + Firestore security rules (so one user can't read another's data), a login/signup UI, and a sync layer in app.js (write-through to Firestore alongside/instead of localStorage). Bigger lift than prior items — real architecture addition, not a small tweak.
